### [OpenAI 推出 GPT-6 Sol 与 Luna 双模型](https://openai.com/index/introducing-gpt-6-sol-and-luna) ⭐️ 9.0/10

OpenAI 发布了新一代前沿模型 GPT-6，并一次性推出两个变体——Sol 与 Luna，分别面向不同的能力与成本权衡场景，以将&quot;前沿智能&quot;带入日常工作。官方公告将 Sol 定位为追求更强能力的版本，而 Luna 则强调以更低的成本提供日常可用性。社区反馈显示，GPT-6 Luna 的定价约为前代 GPT-5.6 Luna 的一半，被视作重要的价格信号。Sol 系列则延续了 OpenAI 自 GPT-5.6 起在编程与工程类智能体任务上的优势，但部分用户担忧其对话风格与表达方式未必完全保留前代模型的&quot;自然感&quot;。整体来看，这次发布延续了 OpenAI 以多档定价覆盖不同工作负载的策略，对个人开发者与企业用户选择模型与套餐都会产生影响。

rss · OpenAI Blog · 9月22日 18:00

**「背景：OpenAI 的模型命名与定价演变」** OpenAI 此前的主力模型为 GPT-5.6，其中包含 Sol、Luna、Astra 等多个变体，分别面向不同的能力与成本取舍，并通过 API 和 ChatGPT 等消费级产品向开发者与企业用户提供服务。OpenAI 的 GPT 系列代际更新通常会带来整体能力的提升，并伴随推理、缓存等基础设施的改进。此次 OpenAI 推出 GPT-6 Sol 与 Luna，将每个代际中同时包含多个价位变体的产品策略延续了下来。

**「影响」** GPT-6 Luna 的 API 价格据评论约为 GPT-5.6 Luna 的一半，而根据 Artificial Analysis 的评估，GPT-6 Sol（max）在编码智能体指数上比前代提升 2 分、但单任务成本降至前代一半，GPT-6 Luna（max）则在该指数上比前代下降 2 分；此外 GPT-6 系列此次仅设 Sol 与 Luna 两档，未保留 GPT-5.6 时代位于中间的 “Terra” 档位，定价与档位结构因此发生实质调整。由于原始公告未提供基准、价格或可用性细节，且外部测评也指出不同变体在能力上各有取舍，开发者与企业在选型时需直接核对官方页面与最新第三方测评以确认是否符合自身工作负载。

**「社区讨论」** 社区讨论集中在三个方向：一是定价，有用户特别指出 GPT-6 Luna 价格降至 GPT-5.6 Luna 的一半，对成本敏感的工作流意义重大；二是使用体验，多名开发者对 5.6 Sol 在编程智能体中的&quot;沟通节奏与工程直觉&quot;表达留恋，担心新一代模型虽然技术指标更强，但缺乏同样的自然协作感；三是套餐选择，实战用户反映在 Claude Code 20x 与 Codex Pro 20x 之间做决定时，使用上限、计费窗口以及 ChatGPT 在 20x 套餐中&quot;几乎不限量&quot;的特性成为关键变量。

### [vLLM v0.30.0 发布：新增多模型支持与持久化权重缓存](https://github.com/vllm-project/vllm/releases/tag/v0.30.0) ⭐️ 8.0/10

vLLM 项目发布 v0.30.0 版本，整合了 315 位贡献者（其中 104 位为新贡献者）的 762 次提交。新增 DeepSeek-V4.1-Flash（含 MXFP8 全 KV 缓存与 FlashMLA V4.1 路径）、DeepSeek-V4-Flash-Vision-Exp、GLM-5.3-Flash（支持 EPLB）、K2-Horizon、Cohere Compass、Bailing V3 VL、Nanbeige4.2 以及基于 AVX512/AMX 的 DeepSeek-V4 CPU 后端等多个模型支持。引入按 GPU 持久化的 weight-cache 守护进程，可将量化并 TP 切分后的权重保留在显存，通过 \`--load-format ipc\_cache\` 与 CUDA IPC 重启引擎，已覆盖 FP4 检查点与多节点 TP；同时新增 Gumbel-max 水印（与推测解码兼容的 dual-key 变体）以及 \`HiSparseConnector\` 主机端稀疏 MLA 解码分层。Model Runner V2 在 FULL CUDA Graph 下实现双批次重叠与推测解码，并将图捕获时间从 12s 降至 2s、H200 上引擎初始化从 28.9s 降至 8.2s。性能方面，Qwen3.8-Flash-Next 与 Kimi K3 在 FP8 索引缓存、分组 FP8 MLA cache 插入、DSV3 步进张量低延迟 GEMM（12-81% 内核加速）等多个路径上获得显著吞吐提升。大规模服务方面加入 PCP+DCP、Elastic EP 复用 CUDA Graph、FlashInfer PCIe IPC 全归约、DeepEP v2 异步 finalize 与 KVCR 二级适配器等。兼容性方面存在多项破坏性变更：伸缩端点需通过 \`--enable-scale-out\` 显式启用、移除 GPTQ 的 \`g\_idx\`、若干 0.29 弃用项被清理、\`python -m vllm.entrypoints.grpc\_server\` 弃用并改用 \`vllm serve --grpc\`、YaRN 与 Transformers 对齐。CUDA 13.0 默认，CUDA 12.9、ROCm 7.2.3、XPU、CPU 等镜像与 PyPI 包同步发布。

### [RBS-Attention:基于半径约束的稀疏预填充加速长上下文 LLM](https://arxiv.org/abs/2609.20971) ⭐️ 8.0/10

针对长上下文大语言模型推理中的预填充瓶颈,论文提出了一种免训练的稀疏预填充方法 RBS-Attention。该方法针对块稀疏注意力中常见的均值稀释问题\(mean dilution,即块中心向量可能掩盖少数高相关 token\),设计了两条互补的选择分支:一条基于质心的基础分支用于捕获平均相关性,另一条救援分支利用关键块的最大半径及其随 prompt、层、头变化的分布,识别被低估的高相关块;两条分支独立设定阈值后再合并掩码,在保持规则块稀疏 FlashAttention 执行路径的同时引入补充块。在 H100 GPU 上,该方法在 Qwen3-30B-A3B-Instruct-2507-FP8 模型、128K 上下文下取得了 20.65 倍独立预填充注意力加速、11.92 倍 vLLM 预填充注意力加速以及 5.97 倍端到端首 token 时间\(TTFT\)加速;在稠密 Qwen3-32B 模型上,整体 RULER 准确率为 88.65,稠密注意力为 89.52,并辅以 LongBench-v2、InfiniteBench 和 Video-MME 的质量评估。

rss · arXiv cs.AI · 9月22日 04:00

**「背景」** 在大语言模型推理中,&quot;预填充&quot;阶段需要在生成第一个 token 之前对整个输入 prompt 进行自注意力计算,其计算量随上下文长度二次增长,因此成为长上下文场景的主要瓶颈。已有的缓解方案包括块稀疏注意力,即仅选择部分关键块参与计算,但块级聚合\(如取均值\)可能掩盖块内少量重要 token,论文将这种失效模式称为均值稀释。RBS-Attention 复用支持规则块稀疏执行的 FlashAttention 内核,并通过 vLLM 这一主流推理引擎进行集成,以保证实际部署可行性。

**「影响」** 对于在 vLLM 上部署长上下文\(尤其是 128K 量级\)LLM 的工程师与团队,RBS-Attention 提供了一种无需重新训练即可获得约 12 倍预填充注意力加速的工具,显著降低首 token 延迟。需注意其质量评估仅覆盖 RULER、LongBench-v2、InfiniteBench 和 Video-MME 等基准,且在 Qwen3-32B 上相较稠密注意力存在约 0.87 个百分点的整体 RULER 准确率差距。

### [PRQuant：面向低开销推理的置换残差量化框架](https://arxiv.org/abs/2609.22106) ⭐️ 7.0/10

PRQuant（Permutation Residual Quantization）是一种训练免费、低开销的低比特量化框架，由 Peiran Wang 等人提出。它针对线性层低比特量化中少量异常值主导精度损失的问题，在 AWQ 风格缩放之后，通过置换将最易引起权重量化误差的输入通道聚集到连续的尾部块，并以离线方式构造这些通道对应的残差权重子张量。推理时，连续布局使激活侧无需执行昂贵的在线 gather 操作，散乱的残差补偿也转化为规则的尾部增强 GEMM，从而显著降低延迟。实验表明 PRQuant 能有效降低下投影重建误差，平滑与残差补偿是主要数值改进来源，置换则提供稳定且小幅的数值收益，并带来硬件友好的连续布局；在五项下游基准测试中，其平均精度优于默认 MXFP4，在 Qwen3-4B-Instruct-2507 与 Qwen3-30B-A3B-Instruct-2507 上分别相对 MXFP4 提升 1.24 和 0.55。

rss · arXiv cs.LG · 9月22日 04:00

**「背景」** 大型语言模型\(LLM\)在推理时通常需要大量显存与算力,因此权重量化成为常见压缩手段。低比特\(尤其是 4 比特及以下\)量化中,极少量的离群激活通道会带来大部分的权重量化误差。代表性方法 AWQ\(Activation-aware Weight Quantization\)通过对激活做逐通道缩放,把激活侧的难度转移到权重的等价缩放上,从而降低量化损失。MXFP4 是 OAMX 微缩格式提案中的 4 比特微缩浮点格式,属于工业界关注的低比特表示之一。然而 AWQ 等在线方案需要在推理时动态执行额外的操作\(如缩放回乘或散乱访存\),会引入显著延迟开销,这正是 PRQuant 试图解决的核心问题。

**「影响」** PRQuant 通过将权重异常通道置换为连续尾部块并配合离线残差补偿，使原本散列的残差补偿转化为常规的尾部增强 GEMM，从而消除了在线 gather 操作带来的额外延迟，为 Qwen3-4B-Instruct-2507 与 Qwen3-30B-A3B-Instruct-2507 等 LLM 的 MXFP4 低比特部署提供了一种训练免费、低推理开销且平均精度优于 MXFP4 与所测 PTQ 基线的路径。但其增益仍属 AWQ 式方法上的增量改进，且论文尚未展示广泛的第三方复现或硬件实测延迟数据。
