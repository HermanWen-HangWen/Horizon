### [校准后路由:分解式 LLM 服务的实证路由研究](https://arxiv.org/abs/2609.16206) ⭐️ 8.0/10

本文对分解式 prefill/decode LLM 服务中的学习型请求路由进行了实证研究,提出一种路由策略,在为请求选择实例时综合考虑精确的 prompt 长度、预测的输出长度、入队后的 KV cache 压力以及 SLO 等级,以估算每个实例上额外的完成时间。策略先在离散事件仿真器中开发,然后在 8 块 NVIDIA A40 GPU\(每块运行一个 vLLM 引擎,使用 NIXL 在 prefill/decode 池间传输 KV cache\)的真实硬件上验证,所有工作负载运行在实测饱和点。在三条混合、突发\(bursty\)的到达轨迹上,该校准路由器的平均 goodput 达到 0.864,而 round-robin、最少负载和长度启发式三种基线在 0.835 到 0.847 之间,且方差最低;它在三条轨迹上均优于 round-robin 和长度启发式,在两条上优于最少负载,在第三条上落后 0.003\(处于运行间噪声范围内\)。论文还量化了硬件校准的重要性:若使用从仿真器得到的常数,goodput 会损失约 4.5 个百分点,约 40% 的尾部延迟优势也会丧失,使评分器退化为接近队列计数;收益随 decode 池规模和流量异构性的增加而增大,但在仅含 3 个实例的池中消失;在极端资源稀缺时,贪心最小化代价会把请求集中到评分最低的实例上,反而不如盲目分散;经过校准后,该学习型路由用 6 块 GPU 即可达到 round-robin 7 块 GPU 的 goodput。

rss · arXiv cs.AI · 9月16日 04:00

**「背景」** 分解式 LLM 服务将计算密集的 prefill 阶段和访存密集的 decode 阶段分别放在不同的 GPU 池上,DistServe、Splitwise、Mooncake 等系统已证明这种分离的高效性。在此类架构中,请求路由决定了每个请求由哪个实例处理,是影响端到端吞吐与延迟的关键决策,但目前缺乏基于真实硬件的系统性研究。

**「影响」** 对在 A40 或类似 GPU 上用 vLLM 部署分解式 prefill/decode 服务的工程团队而言,经过硬件校准的路由信号\(prompt 长度、预测输出长度、KV cache 压力、SLO\)在饱和、突发流量下相比常见启发式可带来约 2–3 个百分点的平均 goodput 提升,并显著降低方差,但前提是路由代价需在真实硬件上校准,否则会损失 4.5 个百分点 goodput 和约 40% 的尾部延迟优势;该方法在 decode 池仅含 3 个实例或处于极端资源稀缺场景时收益消失,应避免使用。

### [元认知引导：从科学家轨迹中恢复低维控制子空间](https://arxiv.org/abs/2609.16245) ⭐️ 8.0/10

arXiv 论文《Metacognitive Steering: Learning the Structure of Scientific Judgment》提出了一种名为“元认知引导”的推理时控制技术。作者基于科学家在真实科研中产生的对比性干预轨迹，从 Kimi 2.6（一个万亿参数的混合专家模型）激活中提取出低维“科学判断”控制子空间，并结合残差分析、跨层奇异值分解与注意力权重子空间对齐等方法，定位出模型中部的关键控制层。该推理时控制器会读取模型当前的认知状态，动态组合针对探索、流程收敛或批判性重审等不同阶段的层特异性干预，但不修改任何模型参数。行为分析显示，这种控制带来了更持续的探索、明确的剪枝以及对证据敏感的合成能力。研究团队将该方法落地为 Columbus-1 自主科研系统，并在其中针对 BlueZ 发现了 8 个可独立复现、可被攻击者触达的漏洞，同时指导了一枚依赖不可节流固体发动机实现推进式回收的十英尺火箭的设计、仿真与制造。需要注意的是，本文为单一预印本，尚未经过独立复现与同行评审；摘要中提及的 Kimi 2.6 命名与时间与目前公开信息存在出入，因此方法成熟度与可复现性仍存在一定不确定性。

rss · arXiv cs.AI · 9月16日 04:00

**「背景」** 近年来,大语言模型\(LLM\)推理控制研究关注如何在不修改模型权重的前提下,通过操纵内部激活来引导模型行为,典型方法包括激活向量加法、条件激活引导等。该论文中将干预施加于一个万亿参数级别的混合专家\(MoE\)模型,其中 MoE 架构在每次前向传播时只激活全部专家中的一小部分,从而在保持大规模参数容量的同时控制单次推理的计算开销。论文涉及的另一相关背景是面向科学发现的长程智能体任务:这类任务要求模型在探索、程序化执行与对证据进行批判性再评估之间不断切换,而常规基于最终结果的训练目标难以对这一过程层面的判断提供监督。

**「影响」** 如果该论文的方法经独立复现验证，将为开发者提供一种无需重新训练或微调即可在推理时动态控制万亿参数 MoE 模型推理策略的途径，使得在长周期科研任务中更系统地实现探索、收敛与批判性再评估成为可能。该方法已在作者部署的 Columbus-1 自主研究系统中得到应用，并据称通过该系统在 BlueZ 中识别出八个可独立复现、可被攻击者利用的漏洞，并指导了一枚十英尺固体火箭的设计、仿真与制造。需要注意的是，目前这些结论仅来自一份未经同行评审的 arXiv 预印本（论文标识的 &quot;Kimi 2.6&quot; 与发表日期存在不一致），尚无独立复现，因此其稳健性和普适性仍存不确定性。

### [Blindspot：面向长程工具调用智能体的安全与拒绝校准基准](https://arxiv.org/abs/2609.16305) ⭐️ 8.0/10

IBM Research 等机构的研究者在 arXiv 发布 BLINDSPOT 基准，针对长程、工具调用型大语言模型智能体，衡量其在多轮对抗交互中能否恰当地执行、拒绝或保持安全校准。该基准目前包含 22 类攻击家族与 35 个场景，覆盖 7 个领域，生成超过 2,500 条长程轨迹，平均交互长度为 14.7 轮，每条轨迹通过执行落地式裁决机制被标记为安全完成、正确拒绝、不安全完成、过度拒绝或不确定五类结果之一。BLINDSPOT 被设计为可扩展的实时仿真框架，支持在不重构评估流水线的前提下新增攻击、场景、工具、策略、领域与智能体配置。研究者用 8 项指标评估了 13 个专有与开源权重模型，结果显示不同模型在安全-效用校准上存在显著差异，且失败往往在数轮安全交互之后才出现，凸显将智能体安全视为轨迹级而非单轮或二元属性的必要性。

rss · arXiv cs.AI · 9月16日 04:00

**「背景」** 随着大语言模型智能体被部署到涉及工具调用、持久状态、动态授权与外部环境反馈的长程任务中，安全风险可能在多轮交互后才逐渐显现，传统的“任务成功”或“攻击成功”单轮评估难以捕捉这一过程。该领域需要专门的基准来衡量智能体在持续交互中的安全校准能力，而目前此类覆盖长程、多攻击家族、跨领域的统一评测仍较为稀缺。

**「影响」** 对于构建与部署工具调用型 LLM 智能体的研究者和企业而言，BLINDSPOT 提供了一个可扩展的执行落地式评测框架，使其能在真实长程交互条件下评估模型的安全-效用校准，而不仅依赖单轮任务准确率。鉴于该基准为新发布且初步结果来自 13 个模型，仍需进一步独立复现以验证其在不同智能体配置下的稳健性。

### [偏见审计能发现偏见，但模型排名几乎等同随机](https://arxiv.org/abs/2609.15995) ⭐️ 8.0/10

一项对十款偏见审计工具与十款前沿模型的实证研究发现，八款工具能够在置信区间排除零的前提下检测到职业性别偏见，但跨工具对模型的排序一致性几乎处于随机水平（Kendall&\#x27;s W=0.07，p=0.83），因此单一审计分数无法支撑模型间比较或监管排名。实验还包含六款刻意较弱的模型作为正控制：当被评估对象的能力差距足够大时，同一工具内部可靠性恢复，但跨工具排序始终无法恢复，表明这些工具衡量的并非同一构念，而是不同构念的不同噪声版本。在偏见方向上，强制选择类审计工具普遍呈现过度纠正，例如在 278 项招聘决策中有 273 项偏向工人阶层候选人；而自由生成与默认指代仍与刻板印象一致。该结论在社会经济地位维度上得到复现，年龄维度上表面上的排序一致在作者的工具纳入规则下消失。两款被广泛引用的直接探测基准已因前沿模型普遍给出中性回答而饱和。作者在 GitHub 公开了原始响应、代码以及从原始数据复算所有报告数值的分析流程，论文编号为 arXiv:2609.15995。

rss · arXiv cs.CL · 9月16日 04:00

**「背景说明」** 新兴 AI 监管要求对高风险系统进行偏见审计，审计分数也开始被用于对模型排名，这两类用途都隐含假设不同审计工具测量的是足够接近的构念。Kendall&\#x27;s W 是一种用于衡量多组排序一致性的统计量，数值越接近 1 表示完全一致，接近 0 则等同于随机排序。

**「影响」** 依赖单一审计分数进行模型选型或合规判定的开发者与监管者需要重新评估方法论基础：检测能力仍然有效，但排名结论缺乏跨工具支持，可能催生对审计工具校准与组合协议的后续工作。

### [KV 缓存分层研究：层级容量比放置策略更决定性能](https://arxiv.org/abs/2609.16215) ⭐️ 7.0/10

本文系统研究了长生命周期 LLM 会话场景下 KV 缓存在 GPU HBM、CPU DRAM 和 SSD 三层存储之间的放置策略与预取策略。研究团队构建了一个离散事件模拟器，并使用随机森林执行时间预测器进行校准，对比了最近使用（recency）、复用频次（reuse frequency）、预测复用（predicted reuse）以及带预取的前瞻 EWMA 预测器，覆盖了聊天、智能体循环和文档问答三类真实工作负载。实验显示，分层缓存使单个 GPU 可支持的并发会话数提升约 73 倍，单会话成本下降约 62 倍，但这些收益主要来自 1:8:64 的层级容量配比本身：在 batch size 为 1 的解码配置下，解码受计算瓶颈限制，吞吐几乎不受放置策略影响，策略主要改变的是 PCIe 迁移流量和首 token 延迟。聊天场景中最近使用策略产生的迁移流量比复用频次低 2.30 倍；智能体和文档问答场景则更适合复用频次策略。作者指出既有 predicted reuse 策略在字节级别与 recency 完全一致，EWMA 预测器虽然改变了行为但在这类工作负载上仍不及复用频次，且所有策略下的预取都未能抵消其带宽开销，即便拥有未来请求知识的预言机（oracle）在迁移流量上也从未胜过无预取方案。

### [用多智能体流水线把 CUDA Tile 内核从 Python 翻译到 Rust](https://developer.nvidia.com/blog/translating-cuda-tile-operations-from-python-to-rust-using-agentic-ai/) ⭐️ 8.0/10

**「背景」** TileGym 中大量生产级 GPU 内核原本用 cuTile Python 或 Triton-TileIR 编写，而新推出的 cuTile Rust（cutile-rs）希望通过扩展 Rust 所有权模型，让同样的 Tile IR 程序能用更安全、显式的宿主语言表达。问题在于，cuTile Python 在调用时通过 JIT 隐式地完成所有特化（分支、dtype、布局都“自动看见”），而 Rust 必须把每个特化点都写在内核签名里，否则就要靠 unsafe 直接发射 Tile IR。作者团队需要把这一库翻译过去，但又不能因为 Python 那种“隐式即正确”的便利换来一堆特化漂移或静默错误。

**「方案」** 作者把翻译拆成一个有界的多智能体流水线：分析器先把参考实现（Python 或 Triton-TileIR，择快者）降到 cuda\_tile dialect 并落盘 analysis.json 与参考 Tile IR，作为后续阶段的“地面真值”；内核写入器只看这份 spec，按 49 条编码规则产出 kernel.rs，并在没有 FFI 的纯 Rust 管道测试中自证正确，再通过 IR 自检比对参考 IR；宿主/FFI 构建器负责 C-ABI 启动函数和 Python 包装，跑真实的 TileGym 测试套件，只有 ALL\_PASS 才放行到基准测试；性能验证器在 B200 上用 CUPTI 设备时间跑 347 对配对配置，要求几何均值落在参考的 0.95 以内。失败时只诊断不改代码：IR-diff 分析师区分“翻译错误”和上游编译器缺陷，剩余性能调查员分析内存操作族、发射配置和 autotune 等残余差距。所有子智能体只通过文件 schema 和带 VERDICT 行的 &lt;VALIDATOR\_OUTPUT&gt; 块通信，编排器只按一张路由表和硬性重试上限做决策，避免一处的 prose 被另一处的 LLM 误读。最终 24 个算子（含约 40 个内核，覆盖 element-wise、flash-attention decode、MLA、MoE 等）全部移植，整体几何均值 0.995，约三分之一反超参考，主要赢面在 element-wise 与归一化核。作者强调这是“结构等价带来的免费性能”：因为两侧前端共享同一 IR 和 tileiras 优化器，只要忠实复现内存操作族、tile 形状和归约轴，Tile IR diff 通过，性能就基本对齐。流水线也优先生成 Rust 惯用写法而非“逐条对齐 IR”的不可读内核，唯一代价是 wall-clock 与设备时间的差异需读者自己区分。整套 skill、validator 脚本以及 softmax、bmm 两个完整样例都已随 TileGym 开源。

**「启示」** 作者的核心论点是：当多个前端共用同一个共享 IR 时，跨语言代码翻译不再需要重新调优，而可以变成一个可被结构化校验的工程问题——用机器可读的 IR diff 取代功能测试兜底，用文件级契约和硬性重试上限把多智能体流水线变成可重复的批处理作业，让“AI 翻译代码”从演示走向可投产。
